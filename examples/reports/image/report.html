Additional layers that can lower risk (2)

Enforce action policy outside the model

How it lowers risk: Have an execution service allow only named operations, permitted argument values, and caller-owned target resources before invoking a tool.

Evidence to verify: Exercise disallowed operations, additional arguments, cross-tenant identifiers, and direct calls that bypass the agent planner.

Residual limitation: Authorized operations can still be harmful when business constraints are incomplete; prompt instructions cannot enforce this boundary.

Verification status: proposed_not_verified

Related controls: AGT-01, AUTH-02, MCP-02

Guidance sources
  • MCP-TOOLS / MCP: Tools
  • OWASP-AGENT-CS / AI Agent Security Cheat Sheet

Isolate tool execution

How it lowers risk: Run the risky tool in a separate, disposable identity with no host mounts, ambient credentials, or unnecessary outbound access.

Evidence to verify: In a test environment, attempt reads outside the workspace, forbidden network connections, and resource exhaustion; retain policy and denial evidence.

Residual limitation: Isolation limits reachable assets; it does not make injected code trustworthy or rule out a runtime escape.

Verification status: proposed_not_verified

Related controls: EXEC-02, SUP-05, OPS-02

Additional layers that can lower risk (3)

Investigate and contain confirmed secret exposure

How it lowers risk: For a real exposed credential, identify reachable systems, revoke or rotate it, and review access records for misuse.

Evidence to verify: Confirm the old credential no longer works and record the exposure window, affected copies, and follow-up owner.

Residual limitation: Successful rotation stops future use of that credential but cannot reverse access or data loss that already occurred.

Verification status: proposed_not_verified

Related controls: AUTH-05, OPS-06

Guidance sources
  • CISA-JCDC / JCDC AI Cybersecurity Collaboration Playbook and Fact Sheet (release notice)
  • NIST-SSDF / Secure Software Development Framework (SSDF) Version 1.1

Use managed credential injection and revocation

How it lowers risk: Load secrets at runtime through an approved store or workload identity; keep them out of source, artifacts, and model context.

Evidence to verify: Test rotation and revocation without disclosing values; inspect build layers and launch metadata for retained copies.

Residual limitation: Deleting a file or hiding a later image layer does not revoke a credential or erase copies already distributed.

Verification status: proposed_not_verified

Related controls: AUTH-05, DATA-01, DATA-06

Guidance sources
  • JOINT-AGENTIC / Careful adoption of agentic AI services
  • MCP-AUTH / MCP: Authorization

Limit credentials available to the workload

How it lowers risk: Give this component a distinct identity and only the downstream scopes and lifetime needed for its approved operations.

Evidence to verify: Use its runtime identity to attempt forbidden service operations, then revoke it and confirm subsequent access fails.

Residual limitation: A compromised component can still use its allowed permissions until credentials expire or revocation takes effect.

Verification status: proposed_not_verified
