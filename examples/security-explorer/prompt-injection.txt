AI032 — External data inserted into privileged LLM instructions [medium]
  Detects: A system or developer message contains an obvious external-input expression. Untrusted data may be interpreted as privileged instructions; local analysis cannot establish exploitability.
  Remediation: Keep trusted instructions separate from untrusted content, label provenance, enforce tool policy outside the model, and test indirect prompt injection and sensitive-action approval.
  CWE: CWE-1427
  A recognized source pattern is a review signal, not proof of reachable exploitation, complete data flow, runtime protection or an acceptance-check pass.
  Partial control mappings: AGT-03
  Agent/MCP relevance: External text inserted into a system/developer message is promoted into the same channel as trusted agent policy. A retrieved document or tool response may then steer planning and sensitive tool arguments.
  Applicability: Trace whether the interpolated value is actually external, configuration-owned or a deliberately trusted instruction; this local pattern does not prove a successful prompt injection.
  Applicability: Moving content to a lower-trust message reduces instruction confusion but does not guarantee the model will ignore adversarial content.
  Fix — Separate instruction construction from data: Keep system/developer templates fixed and application-owned. Put user, retrieval and tool text in the appropriate data/user/tool channel, preserving source labels and a clear distinction between instructions and quoted content.
  Verify: Inject instruction-like text into a retrieved fixture and verify the message assembly never places it in a privileged role.
  Fix — Validate decisions outside the model: Enforce allowed tools, argument schemas, tenant ownership, destinations and sensitive-action approval at the execution boundary regardless of the model output.
  Verify: Use adversarial external content that asks for an unauthorized tool or data export; confirm server-side policy blocks the effect even if the model requests it.
  Fix — Test realistic indirect injection paths: Run a separate bounded adversarial evaluation across documents, memory and MCP results, including source spoofing and multi-step attempts. Record model/version, prompts, outcomes and observed effects.
  Verify: Verify both legitimate task completion and absence of forbidden side effects using an instrumented test harness; do not grade solely from a model claim of refusal.
  Remaining risk: Delimiters, provenance labels and system prompts are not complete injection defenses; model behavior and workflow composition require ongoing tests.
