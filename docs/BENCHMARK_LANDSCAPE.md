# NimeshBuild AI agent and MCP security benchmark landscape

**Research snapshot: 2026-09-19.** This expands [the research basis](RESEARCH.md). It is a curated security landscape, not a claim to include every benchmark published. Government guidance, threat catalogs, verification standards, configuration benchmarks, and behavioral experiments answer different questions. The [NimeshBuild control catalog](SECURITY_CHECKLIST.md) is an independent engineering checklist; references and suggested mappings do not establish conformance, certification, or completed benchmark runs.

Machine-readable records, including scope, version, limitations, and selected control mappings, are in [additional_sources_benchmarks.json](../ai_security_scan/data/additional_sources_benchmarks.json). The existing government, NIST, MCP, and OWASP sources remain in the main research document; CSA is covered in the companion CSA research.

AISVS is an application verification standard, not the MCP protocol specification. Some C10 requirements prescribe stronger application policy; others refer to legacy protocol behavior. For example, its `initialize` and session references require interpretation for the MCP 2026-07-28 core described in [RESEARCH.md](RESEARCH.md). Record applicability and justify a version-specific alternative instead of blindly marking pass/fail.

## Behavioral and adversarial benchmarks

All nine entries below have an original author repository or reference implementation. **None was installed or executed for this report.** The date describes the research, not a frozen code version. Pin the exact repository revision, dataset, scorer, model, and environment before testing.

| Benchmark | Primary sources and research date | Distinct coverage | Important limitation |
|---|---|---|---|
| AgentDojo | [ETH Zurich/Invariant repository](https://github.com/ethz-spylab/agentdojo); [paper](https://arxiv.org/abs/2406.13352), NeurIPS 2024 | Indirect injection in tool workflows, measured together with legitimate task utility. | Simulated applications need adaptation to your tools and authorization design. |
| InjecAgent | [UIUC Kang Lab repository](https://github.com/uiuc-kang-lab/InjecAgent); [paper](https://arxiv.org/abs/2403.02691), 2024 | Focused malicious tool-output cases for tool-integrated agents. | Fixed cases do not represent adaptive attackers or establish permission enforcement. |
| Agent Security Bench (ASB) | [Author repository](https://github.com/agiresearch/ASB); [paper](https://arxiv.org/abs/2410.02644), ICLR 2025 | Multiple agent scenarios and attack/defense methods. | Harness-specific aggregate results do not transfer automatically to production. |
| MCPSecBench | [AIS2Lab repository](https://github.com/AIS2Lab/MCPSecBench); [paper](https://arxiv.org/abs/2508.13220), 2025 | MCP attack playground and testing across different MCP surfaces. | Environment- and client-dependent research setup; not arbitrary-repository or current-spec certification. |
| MCP Security Bench (MSB) | [Author repository](https://github.com/dongsenzhang/MSB); [paper v2](https://arxiv.org/abs/2510.15994v2), **2026-03-24**, ICLR 2026 | Attacks across planning, invocation, and response handling using actual MCP tool execution; includes a utility/security trade-off metric. | Distinct from MCPSecBench. Selected domains, tools, and agent implementations bound its results. |
| MCP-SafetyBench | [Author repository](https://github.com/xjzzzzzzzz/MCPSafety); [paper v2](https://arxiv.org/abs/2512.15163v2), **2026-03-05** | Multi-turn, cross-server safety evaluation using real MCP servers across five application domains and 20 attack types. | Server/service state, harness assumptions, and task selection affect comparability. It does not certify protocol authorization. |
| AgentDyn | [SaFo-Lab repository](https://github.com/SaFo-Lab/AgentDyn); [paper v3](https://arxiv.org/abs/2602.03117v3), **2026-05-07** | Dynamic open-ended tasks with useful third-party instructions; helps reveal defenses that block legitimate instructions excessively. | Extends AgentDojo; account for inherited harness assumptions and avoid treating it as independent evidence across identical cases. |
| AgentHarm | [Inspect Evals reference implementation](https://github.com/UKGovernmentBEIS/inspect_evals/blob/main/src/inspect_evals/agentharm/README.md); [paper](https://arxiv.org/abs/2410.09024), ICLR 2025 | Harmful multi-step user requests and jailbreaks, with corresponding benign tasks. | Misuse evaluation differs from defending an authorized user against third-party injection. Model-based graders, public subsets, license terms, and scoring-version changes matter. |
| BIPIA | [Microsoft repository](https://github.com/microsoft/BIPIA); [paper](https://arxiv.org/abs/2312.14197), initially **2023** | Indirect injection in external email, web, tabular, summarization, and code content. | Primarily an external-content robustness benchmark, not full multi-agent or MCP transport security. Some datasets require separate acquisition under their own terms. |

General capability evaluations such as completing coding tasks, choosing tools, or answering difficult questions are useful utility baselines. They become security evidence only when an explicit threat model, attacker access, policy boundary, observable failure condition, and appropriate scoring rule are added. Merely exposing a capability benchmark through MCP does not make it an MCP security benchmark.

## Evidence plan

1. **Repository checks:** run this deterministic scanner and appropriate language-specific analyzers, secret detection, dependency/CVE review, and build/repository policy checks. Save the scanned revision and exclusions.
2. **Deployment checks:** test actual tokens, authorization scope, tool arguments, target objects, network destinations, filesystem boundaries, tenants, rate limits, stop paths, and audit integrity. Use the applicable CIS configuration benchmarks for the operating system, cloud, container, and orchestration platform as well as the MCP benchmark when available.
3. **Behavioral tests:** begin with AgentDojo or relevant fixed injection cases; add AgentDyn for dynamic workflows and one of the MCP-specific suites for exposed tool ecosystems. Add AgentHarm where malicious-user misuse is in scope. Choose based on architecture, not benchmark count.
4. **Measurement:** preserve benign task completion, attack success, attempted versus completed side effects, data leakage, false blocking, latency, cost, sample size, and unscored/error cases. Document deterministic or model-based adjudication and have humans review consequential ambiguous cases.
5. **Maintenance:** re-evaluate after model, gateway, protocol, memory, tool, permission, or policy changes. Track newly published source releases separately from completed implementation work.

This plan is NimeshBuild's engineering synthesis. A low attack-success result does not compensate for a missing authorization boundary, and a clean static scan does not establish behavioral robustness.
